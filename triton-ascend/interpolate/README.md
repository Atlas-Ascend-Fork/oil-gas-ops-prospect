# Interpolate — separable Cube GEMM

Triton-Ascend 2D/3D linear interpolation. The operator is a drop-in subset of
`torch.nn.functional.interpolate` for `mode="bilinear"` (4D input) and
`mode="trilinear"` (5D input).

For the 5D fast path, the vector gather/blend is expressed as one GEMM per
spatial axis, so the contraction runs on the Cube unit:

```text
Y = X @ W_axis          # W_axis: [in_size, out_size]
```

For an input `[B, C, D, H, W]` the passes are applied last-axis first
(`W -> H -> D`), each with `M = B*C*remaining_spatial`, `K = in_size`,
`N = out_size`.

**Terminology:** the implementation has one Triton kernel function
(`_interp_axis_kernel`). “Three-pass” means that function is launched three
times with different strides/shapes (W, H, D); it is not three separate kernel
definitions, and the three launches are not fused.

The weight matrices are generated by calling PyTorch's own `F.interpolate` on
an identity matrix, which reproduces its fp32 weights exactly.

The kernel uses a persistent grid of `num_aicore` programs that walk a strided
tile list, instead of launching one program per tile.

- `triton_interpolate.py`: `interpolate`, `bilinear`, `trilinear`, autograd
  backward (adjoint GEMMs), CPU fallback, output chunking.
- `tests/triton/interpolate/test_interpolate.py`: CPU and NPU pytest coverage.
- `tests/triton/interpolate/verify_interpolate.py`: verification against
  `F.interpolate`.
- `tests/triton/interpolate/report/`: recorded verification results and the
  environment used for them.

## Usage

```python
from oil_gas_ops_prospect.interpolate import interpolate

# 5D trilinear, align_corners=False
y = interpolate(x, size=(128, 128, 128), mode="trilinear")

# convenience wrappers
from oil_gas_ops_prospect.interpolate import bilinear, trilinear
y2 = bilinear(x2, size=(256, 256))
y3 = trilinear(x3, size=(160, 160, 160))
```

The NPU fast path is used when `OIL_GAS_OPS_INTERPOLATE_IMPL` is `auto`
(default) or `triton`, the input is a 5D fp32 NPU tensor, and the output is at
least 128 MiB. CPU, 4D bilinear, fp16/bf16, `nearest`, `scale_factor`,
`antialias` and small tensors fall back to `F.interpolate`.

4D bilinear deliberately stays on the native kernel; only the 5D trilinear
path is implemented with Cube GEMMs.

## Environment variables

| Variable | Default | Meaning |
| --- | --- | --- |
| `OIL_GAS_OPS_INTERPOLATE_IMPL` | `auto` | `auto` / `triton` / `torch` |

The minimum-output threshold, per-launch chunk budget, and fp32 self-check are
internal implementation details. Test-only overrides are passed by
`verify_interpolate.py` (`--min-bytes`, `--chunk-bytes`, `--allow-fallback`) or
set through the private `_set_test_options` helper; they are not public
environment variables.

## Backward

The 3D path is a first-order `torch.autograd.Function`. The backward is the
adjoint of the same separable operator, run in reverse order:

```text
forward:  W  -> H  -> D
backward: W^T -> H^T -> D^T
```

It reuses `_interp_axis_kernel` with transposed, cached weight matrices, so the
gradient also runs on Cube. 4D uses native `F.interpolate` autograd.
