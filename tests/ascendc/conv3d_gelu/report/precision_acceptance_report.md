# Conv3DGelu / Conv3DGeluGrad 精度与性能报告

简体中文 | [English](precision_acceptance_report_en.md)

按[精度验收报告模板](../../../../docs/zh/develop/precision_acceptance_template.md)填写。15 个 shape 同一次真机执行。前向相对误差全部 `< 1e-5`。输入梯度在补上「进程内第一次切块反向整段丢掉再算」之后，全部 `< 1e-4`。

精度阈值与本仓已交付算子一致，见[算子开发指南](../../../../docs/zh/develop/operator_development_guide.md)。

| 项 | 内容 |

| `torch` / `torch_npu` 版本 | 2.7.1+cpu / 2.7.1.post4 |
| 测试执行人 | 本机，容器 `ascend-npu-ha`，`ASCEND_RT_VISIBLE_DEVICES=7` |
| 测试日期 | 2026-10-28 |

命令：`python3 -u tests/ascendc/conv3d_gelu/test_conv3d_gelu_npu.py --mode all`。

环境：`ACLNN_CACHE_LIMIT=0`（启动 Python 之前设置），`OIL_GAS_OPS_CONV3D_GELU_IMPL=ascendc`，`OIL_GAS_OPS_REQUIRE_ASCENDC_CONV3D_GELU=1`，`torch_npu.npu.conv.allow_hf32=False`。

输出不超过 256MB 时前向和反向一次算完。更大的体积沿 D 按大约 48MB 一块切。进程里第一次切块反向会整段多算一次并丢掉，用户看到的结果是第二次。

## 2. 标杆实现

| 项 | 内容 |
|----|------|
| 标杆实现 | `F.gelu(F.conv3d(...), approximate="tanh")` |
| 标杆设备 | 精度的前向：CPU float32。反向、性能、显存：同一张 NPU 上拆开的 `F.conv3d` + `F.gelu` |
| 对比方式 | 相对误差 `max(\|y_op-y_cpu\|) / max(\|y_cpu\|)`，阈值 `< 1e-5`。输入梯度用最大绝对误差，阈值 `< 1e-4` |

CPU `nn.GELU()` 默认是 erf，不是本算子的标杆。NPU 默认 HF32 会把 conv 误差抬到约 `1e-4`，对拍时关闭。全部用例都带 bias，除了 `k3_24`、`k_dilate`、`k_replicate`。

### 反向

### 边界与异常场景

`groups!=1` 和长度不是 1 或 3 的 `stride` / `padding` / `dilation` 抛 `ValueError`，不计入通过率。空张量、非连续输入和非法数据类型未覆盖。约定仍是 `float32`、`NCDHW`、`groups=1`。

## 4. 性能结果

前向时延。标杆是同一张 NPU 上拆开的 `F.conv3d` + `F.gelu(approximate="tanh")`。每个 shape 先预热 1 次，再计时 2 次（空间边长小于 128 的计时 3 次），计时前后 `torch.npu.synchronize()`。这组数字是前向，不含反向里的重计算。

## 5. 显存

前向峰值是调用期间 `max_memory_allocated`，含已经活着的输入。持有量是带梯度的前向返回后、反向开始前，相对调用前多出来的显存。融合路径不保留 conv 与 GELU 之间的预激活，所以持有量大约少一整份输出。

## 7. 遗留问题

| # | 问题描述 | 严重程度 | 规避措施 | 计划闭环时间 |
|---|----------|----------|----------|--------------|
| 1 | 权重梯度有 NPU 原子累加噪声，未纳入 `< 1e-4` 门槛 | 次要 | 验收看输入梯度 | 未排期 |
| 2 | 空张量、非连续输入、非法数据类型未进本套件 | 次要 | 调用方保持 `float32` / `NCDHW` / `groups=1` | 未排期 |
| 3 | `ACLNN_CACHE_LIMIT=0` 只关 aclnn 缓存。CANN 9.0.0 上新 shape 的前 3 次 launch 仍可能是错的，代码丢掉这 3 次再返回第 4 次；进程内第一次切块反向还要整段多算一次再丢掉。次数是该版本实测，不是接口契约。整组连跑时 `k3_96x192` 前向仍有一次相对误差到 0.98，单独再跑是 1.36e-6 | 主要 | 调用前设置 `ACLNN_CACHE_LIMIT=0`；换 CANN 后必须重测首次 launch，不能假设仍然是「丢掉 3 次」 | 未排期 |

首次 launch 的丢弃次数是主要遗留，规避措施写在上表。除此之外没有严重问题。

## 8. 结论

- [x] 精度达标，前向 15/15，输入梯度 15/15
- [x] 1×1 直写加速比 `1.23` 和 `1.21`，都大于 1.05
- [x] 五组切块 shape 的前向峰值和前向持有量都低于拆开路径
- [ ] 首次 launch 丢弃次数仍是主要遗留，已写明风险和规避；其余遗留为次要

总体结论：**通过**。精度、1×1 加速比和切块显存达标。首次 launch 的丢弃次数是已知风险，见遗留问题 3。
